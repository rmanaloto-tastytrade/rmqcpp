# rmqcpp-order-status-monitor Codex Findings (v2)

- **High – Event loop guidance still contradictory (lines 23, 57-58, 105-106):** Top section says “use rmqcpp-provided Asio `io_context` (epoll/io_uring)” while later saying callers cannot inject an `io_context`. rmqcpp owns a single [`Boost.Asio`](https://www.boost.org/doc/libs/latest/doc/html/boost_asio.html) loop inside `RabbitContext`; no io_uring toggle or caller-supplied context is documented [~/dev/github/bloomberg/rmqcpp/[docs/eventloop.md](eventloop.md):1-8]. *Fix:* remove io_uring mention and consistently state we run the library-managed loop on a dedicated thread.
- **High – Heartbeat/backoff configurability remains implied (lines 63-64, 68, 73, 91-96):** API surface/config still reference heartbeat overrides and recovery/backoff knobs even though rmqcpp exposes none; heartbeats are mandatory and negotiated [~/dev/github/bloomberg/rmqcpp/[docs/heartbeats.md](heartbeats.md):1-17; ~/dev/github/bloomberg/rmqcpp/README.md:21-36]. *Fix:* drop heartbeat/backoff fields or label as future gaps; note current behavior is fixed/automatic.
- **Medium – TLS config fields don’t match rmqcpp (lines 79-80, 91-93):** Doc suggests `verify_hostname` and generic SSL flags; rmqcpp expects `rmqt::SecureEndpoint` + `rmqt::SecurityParameters` (requires CA path; optional client cert/key; verification modes `VERIFY_SERVER` or `MUTUAL`; no disable/hostname-bool) [~/dev/github/bloomberg/rmqcpp/src/rmq/rmqt/rmqt_secureendpoint.h:30-48; ~/dev/github/bloomberg/rmqcpp/src/rmq/rmqt/rmqt_securityparameters.h:25-45]. *Fix:* align config to those parameters and clarify CA is mandatory.
- **Medium – Config sections repeat unsupported knobs (lines 80-82, 95-96):** “recovery” and heartbeat interval fields reappear even after noting they’re not configurable. *Fix:* strike these from config and adapter structs or explicitly mark as unsupported placeholders.
- **Low – Confirm/ack shutdown expectations absent (lines 62-67, 99-104):** While confirms are mentioned, the doc never instructs to drain confirms (`waitForConfirms`) or to always ack/nack per delivery, which are rmqcpp defaults [~/dev/github/bloomberg/rmqcpp/README.md:33-38,134-167]. *Fix:* add a note to observe confirm callbacks and call `waitForConfirms` on shutdown; keep manual ack/nack mandatory.
