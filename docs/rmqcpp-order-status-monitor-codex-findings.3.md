# rmqcpp-order-status-monitor Codex Findings (v3)

- **High – Event loop text still conflicts (lines 23, 57, 105-115):** The doc mentions “use rmqcpp-provided Asio `io_context` (epoll/io_uring when available)” and later “callers cannot inject their own `io_context`.” rmqcpp exposes only the library-owned [`Boost.Asio`](https://www.boost.org/doc/libs/latest/doc/html/boost_asio.html) loop inside `RabbitContext`; there is no io_uring toggle or injectable context [~/dev/github/bloomberg/rmqcpp/[docs/eventloop.md](eventloop.md):1-8]. *Fix:* drop io_uring and any suggestion of a pluggable `io_context`; simply state the `RabbitContext` loop runs on an adapter-owned thread.
- **High – TLS config still misaligned (lines 79-80, 91-105):** Config lists `verify_hostname` and generic SSL flags, but rmqcpp expects `rmqt::SecureEndpoint` + `rmqt::SecurityParameters` (CA path required; optional client cert/key; verification modes `VERIFY_SERVER` or `MUTUAL`; no disable/hostname bool) [~/dev/github/bloomberg/rmqcpp/src/rmq/rmqt/rmqt_secureendpoint.h:30-48; ~/dev/github/bloomberg/rmqcpp/src/rmq/rmqt/rmqt_securityparameters.h:25-45]. *Fix:* rename fields to match `SecurityParameters`, clarify CA is mandatory, and remove hostname-verify toggle unless mapped to the enum.
- **Medium – Unsupported knobs persist (lines 23, 64, 73-74, 80-84, 95-105):** The plan still references heartbeat/backoff/recovery tuning and `connection_error_threshold_ms` alerting, but rmqcpp exposes none of these at the API level; reconnect/backoff are internal defaults and heartbeats are mandatory/negotiated [~/dev/github/bloomberg/rmqcpp/[docs/heartbeats.md](heartbeats.md):1-17; README.md:21-36]. *Fix:* remove these fields or mark them explicitly as future gaps; keep config limited to supported options (host/vhost/credentials/topology/prefetch/confirms/mandatory/TLS, optional compression, client properties, consumer priority/exclusive, shuffle_connection_endpoints).
- **Low – Confirm/ack operational expectations still absent (lines 62-69, 99-114, 117-118):** Doc notes confirms but doesn’t require draining (`waitForConfirms`) or emphasize manual ack/nack every delivery. rmqcpp defaults mandatory=true, requires confirms, and MessageGuard auto-nacks on destruction [~/dev/github/bloomberg/rmqcpp/README.md:33-38,134-167]. *Fix:* add explicit guidance: always ack/nack in handler; observe confirm callbacks and call `waitForConfirms` on shutdown to avoid drops.
