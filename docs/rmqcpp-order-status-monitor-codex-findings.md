# rmqcpp-order-status-monitor Codex Findings

- **High – Event loop control still contradictory (lines 57, 105-107):** Doc now says callers do not inject `io_context`, but later suggests supplying our own `io_context` “if API allows.” rmqcpp owns a single [`Boost.Asio`](https://www.boost.org/doc/libs/latest/doc/html/boost_asio.html) loop inside `RabbitContext`; there is no caller-supplied `io_context` hook or io_uring toggle [~/dev/github/bloomberg/rmqcpp/[docs/eventloop.md](eventloop.md):1-8]. *Fix:* state we run the `RabbitContext` loop on a dedicated thread and drop any suggestion of pluggable contexts/io_uring.
- **High – Heartbeat configurability still implied (lines 63-64, 68, 80-81, 91-92):** The plan/config lists “heartbeat interval override”/`heartbeat_ms` even though heartbeats are mandatory and negotiated; current API does not expose an override or disable switch [~/dev/github/bloomberg/rmqcpp/[docs/heartbeats.md](heartbeats.md):1-17]. *Fix:* remove heartbeat override fields or mark them as future gaps; rely on negotiated heartbeats.
- **Medium – TLS config shape misaligned (lines 63-65, 78-85, 91-93):** Config suggests `verify_hostname` and generic TLS knobs. rmqcpp expects `rmqt::SecureEndpoint` + `rmqt::SecurityParameters` (requires CA path; optional client cert/key; verification enum `VERIFY_SERVER`/`MUTUAL`; no “disable verification”) [~/dev/github/bloomberg/rmqcpp/src/rmq/rmqt/rmqt_secureendpoint.h:30-48; ~/dev/github/bloomberg/rmqcpp/src/rmq/rmqt/rmqt_securityparameters.h:25-45]. *Fix:* rename fields to match `SecurityParameters` (ca/client cert/key, verification mode) and note CA is mandatory.
- **Medium – Recovery/backoff knobs overstated (lines 63-64, 72-73, 81-82, 95-96):** The doc calls for “recovery tuning/backoff” fields and config structs, but rmqcpp’s public surface only offers automatic reconnect/topology redeclare with no exposed backoff controls [~/dev/github/bloomberg/rmqcpp/README.md:26-41]. *Fix:* describe reconnect as automatic with library defaults; if backoff is needed, record as a gap rather than a config field.
- **Low – Config defaults for mandatory/acks/confirms not emphasized (lines 78-84, 99-104):** rmqcpp defaults mandatory flag to true, enforces publisher confirms, and requires explicit acks/nacks [~/dev/github/bloomberg/rmqcpp/README.md:33-38, 134-167]. Doc mentions confirms but not the operational expectations (observe confirms on shutdown; handlers must ack/nack). *Fix:* call out these defaults and the need to drain confirms (`waitForConfirms`) and ack/nack every delivery to match library behavior and legacy semantics.
